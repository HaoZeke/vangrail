* Environment Variables

Read by =Vangrail.from_env=. Nothing here is required: with none of it set, the
engine keeps its deterministic rails and reports every model-backed check as
unchecked.

** Which rails run

| Variable               | Effect                                                     |
|------------------------+------------------------------------------------------------|
| =GUARDRAILS=           | =off=, =0=, =no=, or =false= turns every rail off          |
| =GUARDRAILS_RAILS=     | comma list, or =all=, or =none=                            |
| =GUARDRAILS_ON_ERROR=  | =allow= (default) or =block= when a rail raises            |
| =GUARDRAILS_CACHE=     | =0= turns off the in-process result memo                   |

Rail names for =GUARDRAILS_RAILS=: =input=, =context=, =output=, =grounding=,
=secrets=, =patterns=, =links=, =multiturn=, =privacy=, =markup=, =budget=,
=semantic=, =perplexity=, =bayes=, =linear=, =watermark=. The default set is
=input,context,output,watermark=.

=watermark= is in the default set because Article 50(2) of the AI Act is an
obligation rather than a preference, and a mark nobody switched on is a mark that
is not there. Naming a list without it turns it off, which is right for a caller
guarding text no model generated. =GUARDRAILS_WATERMARK_KEY= signs the mark and
=GUARDRAILS_WATERMARK_ISSUER= names the signer; with neither, the mark still says
the text was generated.

Two are off unless asked for. =multiturn= adds =Rails::Escalation= and
=Rails::Trajectory=, which read conversation history and would otherwise report
every single-turn check as uncertain. =GUARDRAILS_TRAJECTORY_EVERY=2= judges one
turn in two, since the judge costs a round trip and the deterministic rail does
not. =links= adds =Rails::Exfiltration=, which is also switched on by
naming its allowlist. =privacy= adds =Rails::PersonalData=, which rewrites the
question before the model sees it and so is a deployment's call rather than a
default.

** Prompt canary, and the prompt itself

| Variable                 | Effect                                              |
|--------------------------+-----------------------------------------------------|
| =GUARDRAILS_CANARY=      | one or more tokens that must not appear in text     |
| =GUARDRAILS_PROMPT_FILE= | a file whose text must not come back out            |

Generate a canary with =Vangrail::Rails::Canary.generate=, put it in your system
prompt, and name it here. Without a token there is nothing to check.

The canary catches the exact marker and nothing else, so a model that summarises
its instructions walks past it. =GUARDRAILS_PROMPT_FILE= names the file holding
the text that must not come back out and adds =Rails::PromptLeak=, which
compares an answer's sentences against it and redacts the ones reproducing it. A
file, not a variable, because a system prompt in an environment variable is a
system prompt nobody can read; a path that cannot be read raises rather than
building no rail.

** Asking a model rather than a lexicon

| Variable                          | Effect                                              |
|-----------------------------------+-----------------------------------------------------|
| =GUARDRAILS_EMBED_MODEL=          | embedding model, which is what =semantic= needs     |
| =LLMLITE_EMBED_MODEL=             | the same, for the local proxy                       |
| =GUARDRAILS_SEMANTIC_THRESHOLD=   | cosine floor, default 0.75 and uncalibrated         |
| =GUARDRAILS_PERPLEXITY_THRESHOLD= | nats per token, default 7.0 and uncalibrated        |

Both rails are opt-in through =GUARDRAILS_RAILS=, because each costs a round trip
per check and because every document screened on a third-party endpoint is a
document sent there. On a loopback proxy neither is true.

Neither threshold means anything until it is measured against the model in use: a
cosine score belongs to the embedding model and a log probability to the scoring
model. Run =script/embedding_probe.rb= and =script/perplexity_probe.rb=, read the
gap each prints, and set the variable from it. Where the two distributions
overlap, the probes recommend leaving the rail off rather than splitting the
difference.

No embedding model named means no =semantic= rail can be built. Asked for and
unbuildable leaves =Rails::Missing= in the list, so the pass stays uncertain
instead of resting on the offline rails.

** A classifier fitted on your own traffic

| Variable                    | Effect                                        |
|-----------------------------+-----------------------------------------------|
| =GUARDRAILS_LINEAR_MODEL=   | path to a model file fitted by the trainer    |

=linear= adds =Rails::Linear=, a linear classifier over hashed n-grams, and the
gem ships no weights: fit them with =ruby script/train_linear.rb --emit
model.json= against your own corpus. Naming the file is not enough on its own,
because the rail is off unless =GUARDRAILS_RAILS= asks for =linear=; asked for
with no model, it reports itself unchecked rather than passing. A path that
cannot be read is reported the same way, with the reason attached.

** What an answer may link to

| Variable                  | Effect                                             |
|---------------------------+----------------------------------------------------|
| =GUARDRAILS_LINK_HOSTS=   | comma or space list of hosts an answer may link to |
| =GUARDRAILS_IMAGE_HOSTS=  | hosts it may auto-load images from                 |

Naming =GUARDRAILS_LINK_HOSTS= is the opt-in, because the empty allowlist means
no links at all: right for an application that named its hosts, wrong to impose
on one that never mentioned links. =GUARDRAILS_IMAGE_HOSTS= defaults to the
link list and can be set narrower, since an image is fetched without a click.
Subdomains of a listed host are included.

** Where the model-backed rails call

| Variable                    | Effect                                          |
|-----------------------------+-------------------------------------------------|
| =GUARDRAILS_PROVIDER=       | pin a registered provider by name               |
| =GUARDRAILS_API_BASE=       | an endpoint nobody registered                   |
| =GUARDRAILS_API_KEY=        | its credential                                  |
| =GUARDRAILS_MODEL=          | classifier, where the provider hosts one        |
| =GUARDRAILS_JUDGE_MODEL=    | instruct model for policy and grounding rails   |
| =GUARDRAILS_REASONING=      | =1= asks a classifier for a written rationale   |

An unknown =GUARDRAILS_PROVIDER= raises rather than falling back, because an
operator who named an endpoint deserves to see it fail.

** Describing a shared gateway

No institution's endpoint ships in this gem. A deployment describes its own
without writing code:

| Variable                          | Effect                                |
|-----------------------------------+---------------------------------------|
| =GUARDRAILS_GATEWAY_NAME=         | its name in the registry              |
| =GUARDRAILS_GATEWAY_API_BASE=     | base URL; presence enables the rest   |
| =GUARDRAILS_GATEWAY_API_KEY=      | credential, first source tried        |
| =GUARDRAILS_GATEWAY_KEY_FILE=     | a file holding the credential         |
| =GUARDRAILS_GATEWAY_PASS_ENTRY=   | a =pass= entry holding it             |
| =GUARDRAILS_GATEWAY_MODEL=        | its model, used as the judge unless   |
|                                   | the next line names one               |
| =GUARDRAILS_GATEWAY_JUDGE_MODEL=  | instruct model                        |
| =GUARDRAILS_GATEWAY_GUARD_MODEL=  | classifier, if it hosts one           |
| =GUARDRAILS_GATEWAY_GUARD_PRESET= | =apriel_guard= or =llama_guard=       |

Credentials resolve most explicit first: the variable, then the file, then
=pass=. An override replaces the configured source rather than being tried
before it, so pointing a key file at nothing means there is no key. Whichever
variable holds the credential, the same name with =_FILE= appended names a file
holding it instead, so a deployment that already documents its own variable does
not have to rename it.

** Overriding a provider by its own name

Every registered provider also reads two variables named after itself, its name
upcased with anything but a letter or digit turned into an underscore:

| Variable            | Effect                                     |
|---------------------+--------------------------------------------|
| =<NAME>_API_BASE=   | send this provider's calls somewhere else  |
| =<NAME>_API_KEY=    | the credential to use for them             |

So the provider registered as =llmlite= reads =LLMLITE_API_BASE= and
=LLMLITE_API_KEY=, and one registered as =my-hub= reads =MY_HUB_API_BASE=. These
cannot be listed exhaustively here, because the names come from whatever a
deployment registered. They apply to one provider; =GUARDRAILS_API_BASE= above
describes an endpoint nobody registered at all.

** The local proxy

| Variable            | Effect                                    |
|---------------------+-------------------------------------------|
| =LLMLITE_HOST=      | default =127.0.0.1=                       |
| =LLMLITE_PORT=      | default =8760=; =GROK_SHIM_PORT= also read |
| =LLMLITE_MODEL=     | instruct model; none compiled in          |
| =GROK_LLMLITE_MODEL= | the same, read where =LLMLITE_MODEL= is unset |
| =LLMLITE_API_KEY=   | credential; none compiled in              |

Availability is decided by a TCP connect, not a request: a proxy that is not
running is the ordinary case, and finding that out has to cost microseconds.

** Running something else entirely

| Variable                       | Effect                                       |
|--------------------------------+----------------------------------------------|
| =GUARDRAILS_CONFIG=            | a configuration folder to load and run       |
| =GUARDRAILS_SERVER=            | call an existing NeMo Guardrails server      |
| =GUARDRAILS_CONFIG_ID=         | which server config to use                   |
| =GUARDRAILS_SERVER_API_KEY=    | credential for that server                   |

=GUARDRAILS_CONFIG= wins over the direct rails; =GUARDRAILS= off wins over
everything.
